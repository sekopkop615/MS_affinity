About

MS_affinity is the web interface for MonsterScan. The contract keeps a registry of token scans and address scans; reporters submit risk tiers (0–10) and flag hashes; the keeper manages whitelist, blacklist, and risk thresholds.

This demo runs in-browser; connect a wallet and contract address for mainnet. All role addresses and the report vault are set at deployment (immutable). No backend is required for the demo: scans, tokens, and lists are stored in memory and reset on refresh.

On-chain, the keeper can pause the contract, withdraw fees from the report vault, and configure risk thresholds per tier. Use the filters above to narrow scans by risk tier or target address. Pagination is applied to the scans table.

FAQ

  • What is MonsterScan?
    MonsterScan is an on-chain crypto scanner contract. It stores token and address scan results with risk scores (0–10), whitelists, blacklists, and reporter roles. MS_affinity is its web UI.
  • Who can submit a scan?
    Only addresses registered as reporters by the keeper can submit scans. The keeper is set at deployment and cannot be changed.
  • What is a risk tier?
    A number from 0 (safest) to 10 (highest risk). Low is 0–3, medium 4–6, high 7–10. Thresholds per tier can be configured for logic like “exceeds threshold for tier 5”.
  • What is the report vault?
    An immutable address set at deployment. Fees or rewards can be sent there; the keeper can withdraw to a recipient. This UI does not send funds.
  • Can I use this on mainnet?
    Yes. Deploy the MonsterScan Solidity contract, then point this interface to its address. You will need a wallet (e.g. MetaMask) to sign transactions for submitScan, whitelist, etc.
  • Why does “Connect” show a random address?
    In demo mode there is no real wallet. Connect simulates a random address for testing. On mainnet you would integrate with window.ethereum to get the real account.
  • How do I add a token?
    Use “Register token (demo)”. Enter a symbol and the token contract address. Only the keeper can register tokens on-chain; this demo mimics that in memory.
  • What is the scan ID?
    A unique identifier for a scan, typically the keccak256 hash of a string. This UI uses SHA-256 for demo; on-chain the contract may use bytes32 (keccak256). Leave blank to auto-generate.
  • Is the contract upgradeable?
    No. MonsterScan uses immutable keeper and report vault; there is no proxy or upgrade mechanism. Deploy a new contract to change roles or logic.
  • Where is the source code?
    MonsterScan.sol and MSJ.java are in the contracts folder. This page (MS_affinity) is a single-file HTML/CSS/JS interface. Not audited; use at your own risk.

Glossary

Terms used in MonsterScan and MS_affinity.

Keeper
Address that deployed the contract; can register tokens, reporters, whitelist/blacklist, set risk thresholds, and pause.
Reporter
Address registered by the keeper; only reporters can submit scans (submitScan, submitScanBatch).
Report vault
Immutable address set at deployment; receives ETH via receive(); only this address can call withdrawVault().
Scan ID
Unique bytes32 identifier for a scan (e.g. keccak256 of a string).
Risk tier
Number 0–10: 0 = safest, 10 = highest risk. Low 0–3, medium 4–6, high 7–10.
Target
Ethereum address that was scanned.
Flags hash
Optional bytes32 hash of flag bits or metadata submitted with a scan.
Whitelist
Addresses marked as trusted by the keeper.
Blacklist
Addresses marked as risky or blocked by the keeper.
Token scan ID
Unique identifier for a registered token (e.g. keccak256(symbol)).
Category
Optional grouping for scans; registerCategory(nameHash) returns a categoryId used in submitScanWithCategory.
Threshold
Per-tier numeric threshold; exceedsThreshold(scanId, tier) checks if the scan meets or exceeds it.

How it works

  1. The keeper deploys the MonsterScan contract (no constructor args). Keeper = msg.sender; report vault is set in source.
  2. The keeper registers reporters via registerReporter(address). Only these addresses can submit scans.
  3. Optionally the keeper registers categories via registerCategory(keccak256("Name")) and tokens via registerToken(tokenScanId, address, symbolHash).
  4. The keeper may set risk thresholds per tier via setRiskThreshold(tier, value) and add/remove whitelist/blacklist entries.
  5. Reporters call submitScan(scanId, target, riskTier, flagsHash) or submitScanWithCategory(..., categoryId) to record a scan.
  6. Batch submission is available: submitScanBatch(scanIds, targets, riskTiers, flagsHashes) up to MSC_BATCH_LIMIT (64) per call.
  7. Frontends and indexers query scans via getScanIdsPaginated(offset, limit), getScan(scanId), addressStatus(target), and related views.
  8. The report vault can receive ETH (receive()); only the vault address can call withdrawVault() to pull funds out.
  9. The keeper can pause/unpause the contract; when paused, no new scans or list changes (except withdraw and unpause).
